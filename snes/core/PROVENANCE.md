## What is here

Only the emulation core: the 65816 CPU, PPU and tile renderers, DMA/HDMA, the
SPC700 and DSP (`apu/`), and the cartridge chips (Super FX, SA-1, S-DD1,
SPC7110, SETA, DSP-1/2/3/4, C4, OBC1, S-RTC, MSU-1, BS-X). The file list is the
one upstream's libretro build compiles (`libretro/Makefile.common`) minus
`libretro.cpp` and the NTSC filter, plus the `.cpp` files those sources
`#include`. `sources.mk` lists the translation units to compile; the
`apu/bapu` files it leaves out are included by `smp.cpp` and `sdsp.cpp`.

Not taken: every GUI port (gtk, qt, win32, macosx), netplay, the debugger, the
shaders, the Vulkan/GL output, the zip/JMA readers, libretro glue, and
`apu/bapu/smp/debugger`.

All the `*.h` files at the top of the upstream tree were copied (they are
small and the sources include them freely).

## Local changes

The core is Snes9x 1.63 plus the changes below. Everything not listed is
byte-identical to upstream. Three kinds of change: **A** speed-ups that are exact (same frames
and audio as without them; each can be switched off, see the end), **B** upstream fixes taken from
the Snes9x master after 1.63 (commit ids are upstream's), **C** hooks and glue for the Vita frontend.

| `fxfast.cpp` (new, 20 Nov 2026, 2.0), hooks in `fxinst.cpp`, `fxinst.h`, `fxemu.cpp`, `fxemu.h`, `cheats2.cpp` | A block-cache Super FX interpreter written for this tree (own code, same licence as the rest of the core; the hand-written assembly of other Snes9x forks was only read as a reference for how fast the job can be and nothing of it, or of any GPL emulator, was copied). It decodes a run of GSU instructions once into a block of ops (the ALT / FROM / TO / WITH prefixes folded into the op, the source and destination registers resolved) and runs the block with computed-goto dispatch; a block remembers the two blocks it went on to last (no hash lookup at most block ends), the arithmetic ops have variants that skip the flag writes no later op of the block reads (dead-flag elimination), and the function exists once per plot depth (blocks are dropped when a game changes the depth). The cycle model is kept bit-exact: each block carries its fetch and cache-line cost, computed with the same rules as `fxinst.h` (`FETCHPIPE`, the 16-byte line fill, the delay slot's own fetch), and a block is only entered when the budget of the line covers it, else the last instructions of the slice are run by the reference interpreter (`fx_run_ref`, the former `fx_run`). The lazy flag fields, the pipe byte, the prefix state and the register garbage that snapshots save are produced exactly as the reference does. Anything unusual (code in RAM, a delay slot that is not simple, a cache base that is not 16-byte aligned, the flat-budget mode) runs the reference. Blocks are dropped when a cheat writes the ROM image (`cheats2.cpp`) and on reset. The cache RAM at $3100-$32ff is timing only in this core (code is always read from the program bank), so a CPU write there needs no invalidation. Switch: `gsu_fast` (host option, 1 by default). Proof: `snes/twin/gsu_check.sh`, gate step `snes-gsu-fast`, and the `FX_SHADOW` build (every slice run twice, whole GSU state, RAM and line flags compared). Results are identical to the reference interpreter (frame hashes, sound, saved state) on Doom, Stunt Race FX and Yoshi's Island, 3600 frames at four clocks, and on the 58 GSU test ROMs (x86, armhf under qemu, ThreadSanitizer clean with the picture and sound threads; second pass of 21 Nov 2026: dead flags, chaining, per-depth copies). |
| `tileimpl.h` (20 Nov 2026, 2.0) | `DrawBackdrop16`: a group of eight backdrop pixels that nothing has drawn on yet, with plain add / subtract colour math and the sub screen showing through part of the group (so the group is not one colour), is made by the vector form `CalcRow8` that the tile rows already use, instead of pixel by pixel. Same colours, same depth bytes (frame hashes of the 15 owner games, 3000 frames, wide view off and on, identical to the tree before). A sky gradient with a far layer on the sub screen (Super Mario World, Yoshi's Island) is the case; it is also most of what the wide view's backdrop pass draws there. |

Merge notes. **Super FX**: the frontend's pacing hooks are unchanged. The measured GSU time
still feeds `SuperFXClockMultiplier`; in cycle mode the multiplier scales the per-line budget
(`H_Max * multiplier / 100` GSU cycles) as it scaled the instruction count before. The Winter Gold
hack's counters are file-level and are cleared in `S9xResetSuperFX`. After a state load the GSU
cache mask is cleared (`snapshot.cpp`). The frontend option `gsu_cycles=0` selects the old flat
per-line budget (`Settings.DisableGSUCycleMode`; effective at the next ROM load).
**SaveSRAM**: `CMemory::SaveSRAM` in `memmap.cpp` now writes through `S9xSafeWriteFile`
(temp file, read-back check, rename). The frontend does not call it (`S9xAutoSaveSRAM` is an
empty stub; `frontend/host.cpp` saves battery RAM itself), so this is a safeguard for other users of
the core.

| `tileimpl.h`, `globals.cpp` (22 Nov 2026, 2.0) | **Mode 7 with a normal-width plotter, one line in two steps.** `DrawTileNormal` (BG1, not mosaic, not hi-res) first fetches the line's pixel bytes into a 128 byte buffer (four pixels a step: plane coordinates and the two byte addresses as vectors, the two byte loads scalar; no per-pixel range test when the first and the last pixel of the run are inside the plane or the plane wraps, which is exact because the position is linear in the pixel index) and then draws the buffer eight pixels at a time with `DrawRow8` (the tile rows' own routine: same depth test, same colour maths, same stores). | `gfx.cpp`, `gfx.h`, `ppu.h`, `ppu_mt.cpp`, `widecap.h` (22 Nov 2026, 2.0) | **Margin strip cache.** The wide view's strips of a line (every pass) that an earlier frame drew under the same inputs are kept and not drawn again. A line's key is a 128 bit hash of what its passes read: the line record (the layers, scroll and Mode 7 rows the batch can draw; the rest of the record is left out of the key, the adapter still gets all of it), the window tables, `BG_Forced`, `ForcedBackdrop`, `MaxSpriteTilesPerLine`, `Transparency`, `GFX.FixedColour`, the colour table (hash of `IPPU.ScreenColors`), the hardware sprite list of the line (tile counts of the sprites inside the picture, every field the margin drawing reads of the ones that reach an edge) and the sprites wholly in the left margin, and the write counters of the 2 KB VRAM blocks the enabled layers' tile maps and character data (Mode 7: the first 32 KB) and those sprites can read. Nothing the emulation reads changes. Proof: `fast_compare.py` (as above, `wide_cache` on and off), `wide_cache_verify` on every owner game, `snes/twin/wide_fuzz.cpp` (random register, VRAM, CGRAM and OAM writes between frames) and six deliberately weakened keys (`WCACHE_NEGATIVE_CONTROL`): see snes/WIDE-INTEGRATION.md, "Mode 7 pixel loop and the margin strip cache". |
| `ahead.cpp`, `s9x_ahead.h` (new, 25 Nov 2026, 2.0, MIT like `ppu_mt.cpp`), hooks in `apu/apu.cpp`, `apu/apu.h`, `apu/bapu/dsp/SPC_DSP.h`, `controls.cpp`, `controls.h`, `fxemu.cpp`, `fxemu.h`, `sa1cpu.cpp`, `sa1.h`, `dsp3.cpp`, `dsp.h`, `msu1.cpp`, `msu1.h`, `gfx.cpp`, `gfx.h`, `ppu.h` (`S9xTilesDirty`: the tile cache lines of `REGISTER_2118` as a function, so `ahead.cpp` holds no copy of Snes9x code) | **Run-ahead's light snapshot** (Quick response, `snes/frontend/host.cpp` `snes_host_run_frame_ahead`). The hooks only give the snapshot access to file-static state: `S9xControlAheadCopy` (pad read positions, latch, devices), the cheat engine's memory of each code (`saved_byte`, `cond_true`, read from `Cheat` directly: without it a conditional code whose condition the look-ahead frame saw first never fired), the eight rows of an SA-1 type 2 character conversion under way (the scratch area at the top of the ROM block), `S9xSuperFXAheadCopy` (the Winter Gold cel hold), `S9xSA1AheadCopy` (the SA-1 replay engine), `S9xDSP3AheadState` (DSP-3's command function pointer), `S9xMSU1AheadCopy` (registers, sample position, the files moved back only when they moved), `S9xAPUAheadSave` / `S9xAPUAheadRestore` (SPC700, DSP but the separate echo buffer when that option is off, ports, resampler contents; run as jobs in the APU thread's stream when it is on), `SPC_DSP::ahead_echo`, and in `SetupOBJ` a copy of the sprite tables the first time the look-ahead frame rebuilds them (`S9xAheadObjArm` / `S9xAheadObjRestore`; they give the range and time-over flags). ### Switches that prove the exact speed-ups

Build with `-DCBOC_NO_WAI_SKIP` (every WAI pass is interpreted) and `-DCBOC_NO_SA1_REPLAY`
(`sa1_code_in_rom()` is false, so every SA-1 instruction is interpreted). `snes/twin/exact_check.sh`
builds both ways and compares frames and audio of every ROM bit for bit. The threaded workers are
checked against the single thread by `snes/twin/mt_compare.py`.

The frontend that drives this core is in `../frontend` (MIT) and does not modify it. To update to a
newer Snes9x: copy the same file list, re-apply the changes above (search for `S9XP_`, `CBOC_`),
and run `snes/twin/conformance.py`, `exact_check.sh` and `mt_compare.py`.

### D. State loads that are not trusted (20 Nov 2026, 2.0)

A snapshot comes from a file or from the host of an online game, so it is treated as hostile (`tools/statefuzz`, `snes/twin/statefuzz.cpp`).
All changes are in `snapshot.cpp` and mark themselves `CBOC-Vita`:

- `SnapshotTimingSane` runs before the machine is touched: the timing block (line and event positions, counters, event numbers) must be
  one this machine can produce, else the load is refused (`SNAPSHOT_INCONSISTENT`) and nothing has changed.
- DMA channels: the transfer mode is 3 bits and the flags are flags (they index tables).
- PPU registers that index tables or select a mode (brightness, BG mode, OBJ size / name base, BG bases and sizes, sprite fields, VMA
  increment and its derived mask, screen height) are brought back inside what the register write can produce.
- Super FX: the block stores host pointers as offsets and table selectors. The chip's memory pointers (RAM and ROM bank tables, the
  cache, the screen pointers) are rebuilt from the machine's own values, selectors are masked, the screen pointers are derived again
  (`SnapshotSuperFXKeep` / `SnapshotSuperFXSanitize`). A chip block in a state for a cart without that chip (Super FX, SA-1) is ignored.
- Audio: the SPC/DSP block is copied into a buffer padded with zeros (the DSP's `extra()` length byte could read past the block).
  `apu/bapu/dsp/SPC_DSP.cpp` (`copy_state`, marked `CBOC-Vita (H1)`): each voice's sample buffer position, BRR block offset and
  interpolation position, the envelope mode and the DSP's phase are held to the ranges the DSP keeps them in (a damaged position read past the
  voice's 24 sample buffer in `decode_brr`; found by the fuzzer on a long run, seed 7).
- The Super FX screen pointers are derived again after a load, but the chip's own bookkeeping (`vPrevMode`, `vSCBRDirty`,
  `vPrevScreenHeight`) is left as the state had it, so a genuine state runs on bit for bit as the uninterrupted machine (the load proof on a
  Super FX game found the difference).
